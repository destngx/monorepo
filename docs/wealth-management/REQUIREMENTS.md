## 1. Product summary

- **User**: a single Vietnamese professional managing personal wealth (VND bank accounts, Sacombank credit cards, Binance crypto, Vietnamese fund certificates (IFC/CCQ), SJC gold, loans/debts, savings goals). Single-tenant, no multi-user.
- **System of record**: one Google Sheet (`GOOGLE_SHEETS_ID`). The app reads and writes the sheet; it never owns financial data itself. Sheet formulas (e.g. GOOGLEFINANCE USD/VND conversion, running balances) are part of the system and must not be bypassed.
- **Value**: one place to see net worth, cash flow, budget burn, card cashback efficiency, debts and goals; fast transaction entry (manual or from parsed bank emails); and AI/market intelligence for VN investments.
- **Base currency**: VND (`vi-VN` formatting, 0 decimals). Timezone `Asia/Ho_Chi_Minh`. UI language mixes EN and VI.
- **Target architecture** (decided, mirrors the graph-weave consolidation in `13c544a`): one Nx project `wealth-management` at `apps/wealth-management/`: Go engine at the project root, SvelteKit UI in `ui/` built as a static SPA (`adapter-static`, base `/ui`) and served by Fiber. One process, one origin in production. MCP server exposes the same capabilities to external agents.

### 6.2 Smart Capture: AI-suggested transactions from materials

The user collects whatever evidence they have of balance changes (screenshots from bank apps such as Sacombank, Vietcombank, Techcombank; e-wallets such as MoMo, ZaloPay, ShopeePay, Viettel Money; Binance; copied SMS, push notifications, or email text) and drops it all in at once. AI reads everything, proposes transactions, and the user approves what goes into the sheet. **Nothing is written without explicit approval.**

**Flow**: collect materials → extract events per material → consolidate across materials → match accounts, categorise, dedup against the ledger → reconcile balances → review and edit → commit approved → done.

**Implementation notes** (engine `service/ai/capture.go`, `domain/capture*.go`; UI `/transactions/capture`):

- The model only reads materials: one vision call per material (3 in parallel) with prompt `tasks/capture-extract` (variables `{{today}}`, `{{accounts}}`, `{{aliases}}`) plus the engine's JSON contract. Text materials are PII-masked first.
- Consolidation, account matching (alias rules, last-4 digits, distinctive name words), own-transfer pairing, ledger dedup and balance reconciliation are deterministic engine code, so `tasks/capture-consolidate` is not used: the same inputs always give the same suggestions.
- Categories: `CaptureRules` payee rule → payee history → one batched model call with the optional prompt `tasks/capture-categorize` (variable `{{categories}}`; validated against the category list and the card's cashback tags) → `Uncategorized`, flagged for review.
- `CaptureRules` tab (created on first save): `Kind | Pattern | Value | Updated`, kind `alias` (pattern → account) or `payee` (payee → category); matching ignores case and Vietnamese accents. HTTP `GET/POST /api/capture/rules`, MCP `GetCaptureRules` / `SaveCaptureRules`.
- `POST /api/ai/capture` streams NDJSON progress events then `{"type":"result"}`; MCP `SuggestTransactionsFromMaterials` returns the same result. Neither writes; commits use `POST /api/transactions/batch`.
- Materials live in the browser tab and the request only; the engine never logs, caches or writes them.

## 10. AI

### 10.1 Architecture (decided)

The engine removed its in-process LLM layer on 2026-04-02 (`f4ec0ec`) in favour of MCP-first. Revision 2 brings in-app AI back: **all AI features from the legacy app (analysis, reviews, briefings, advisor, chat, think tank) are in scope and run inside the engine**, plus Smart Capture (§6.2).

- **Engine `ai` port** (hexagonal): `Complete`, `CompleteJSON` (schema-validated), `Stream`, tool calling, and **image input** (required by Smart Capture). Provider adapters behind it; the provider is configuration, not code (D10).
- **Deterministic first**: every number (net worth, budget actuals, health score, cashback, technicals) is computed by the engine (§12) and passed to the model as facts. The model explains and recommends; it never computes ledger figures.
- **MCP stays** as the interface for external agents, exposing the same data and the same AI use cases.
- One AI use-case service per feature, each with: prompt keys, input builder, output schema, cache policy, and tests against a stubbed `ai` port.

**Configuration** (engine env, `.env.local` for local runs). AI is disabled, and `GET /api/ai/status` says why, until `AI_BASE_URL` and `AI_MODEL` are set; the AI routes need the Google Sheet because prompts and data come from it.

## 12. Canonical business rules

Legacy computes several of these differently on different pages. These are the single definitions to implement **in the engine** (so UI, AI and MCP agree).

| ID         | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Status                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| WM-RULE-1  | **Net worth** = Σ account balances (assets positive, card debt negative) − Σ loan `yearlyRemaining`. L's Accounts page excludes loans while the Dashboard includes them; use one definition everywhere (confirm, D3).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | ✅ E                                       |
