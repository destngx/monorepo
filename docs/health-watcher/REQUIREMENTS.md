## 1. Product summary

- **Problem**: health results arrive from dentists, hospitals and clinics as printed pages, PDFs, record books, photos and imaging films. They sit on a bookshelf. Finding an old CT report means searching by hand, and lab values can't be compared across years.
- **Users**: a family or another small group. One person may manage records for others (children, parents), and one login may belong to more than one group.
- **What the app does**, in priority order:
  1. Stores every original (paper scan, PDF, photo, film photo) with its date, person, provider and type, so any record can be found by search.
  2. Reads each document into structured data: lab values with units and the reference range printed on that paper, diagnoses, prescriptions and procedures. A person approves every reading before it counts.
  3. Draws each metric over time, across clinics, with its reference range.
  4. Gives an AI review of the approved data. Each comment cites its source. The review is for reference only and never replaces a doctor.
- **Not in scope**: diagnosis, treatment advice, reading medical images with AI, sharing with clinics, native mobile apps (iOS installs need a paid developer account, see D2).
- **Locale**: documents are mostly Vietnamese, some English. Timezone `Asia/Ho_Chi_Minh`. Dates show as `dd/MM/yyyy`.
- **Architecture**: one Nx project `health-watcher` at `apps/health-watcher/`. The Go engine sits at the project root (hexagonal: `domain/`, `port/`, `service/`, `adapter/`). The SvelteKit UI lives in `ui/`, built as a static SPA (`adapter-static`, base `/ui`) and served by Fiber. One process, one origin, the same as wealth-management.

## 2. Tenants and people

A **tenant** is a family or group. Everything the app stores belongs to exactly one tenant.

| ID       | Requirement                                                                                                                                                                                                                                                        | Status |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| HW-TEN-1 | **Tenant**: has a name (e.g. `Nguyen family`). The user who creates it is its first owner.                                                                                                                                                                         | ✅ B   |
| HW-TEN-2 | **Membership**: a user belongs to one or more tenants with a role. `owner` manages members and settings and can delete the tenant. `editor` adds, edits and approves records. `viewer` only reads. A tenant always keeps at least one owner.                       | ✅ B   |
| HW-TEN-3 | **Person**: the subject of records. A person belongs to one tenant and has a display name, date of birth and sex at birth (reference ranges depend on both). A person may be linked to a user (an adult who logs in) or not (a child, a parent who never logs in). | ✅ B   |
| HW-TEN-4 | **Invites**: an owner creates a one-time invite link with a role, valid for 7 days. Opening it signs in or registers the user and adds the membership.                                                                                                             | ✅ B   |
| HW-TEN-5 | **Tenant switch**: a user in several tenants picks the active tenant in the header. The choice is kept per browser. Every request carries the active tenant, and the engine checks the membership on each request.                                                 | ✅ B   |
| HW-TEN-6 | **Isolation**: every table that holds tenant data has a `tenant_id` column. Repositories take the tenant from the request scope and never accept it from the request body. A test suite proves a member of tenant A gets `404` for every resource of tenant B.     | ✅ B   |

## 4. Records model

```
Tenant ─┬─ Person ─┬─ Visit (date, provider, specialty, note)
        │          │    └─ Document (one original file, its pages and OCR text)
        │          │         ├─ Observation (one measured value)
        │          │         └─ Finding (diagnosis, prescription, procedure, imaging report)
        │          └─ Review (an AI review of approved data)
        └─ Provider (hospital, clinic, dentist, lab)
```

| ID       | Requirement                                                                                                                                                                                                                                                                                               | Status |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| HW-REC-1 | **Visit**: one encounter on one date with one provider for one person. Type is one of `checkup`, `lab`, `imaging`, `dental`, `specialist`, `emergency`, `inpatient`, `vaccination`, `other`. A visit can exist with no documents.                                                                         | ✅ B   |
| HW-REC-2 | **Document**: one original, kept byte for byte (HW-OPS-2). Kind is one of `lab_result`, `imaging_report`, `imaging_film`, `prescription`, `discharge_summary`, `dental_record`, `record_book_page`, `invoice`, `other`. A document has pages, and each page has OCR text.                                 | ✅ B   |
| HW-REC-3 | **Observation**: analyte, value (number, or text for results like `Âm tính`), unit, the reference range printed on the paper (low, high, or text), the paper's own flag (H, L, `*`), the sample date and the source document and page. Linked to the metric catalog (HW-MET-1) when the analyte is known. | ✅ B   |
| HW-REC-4 | **Finding**: kind (`diagnosis`, `prescription`, `procedure`, `imaging_report`, `allergy`, `vaccination`, `note`), text as written, an optional ICD-10 code when the paper prints one, and the source document and page. Prescriptions keep drug, dose, frequency and duration.                            | ✅ B   |
| HW-REC-5 | **Provider**: name and kind (`hospital`, `clinic`, `dental`, `lab`, `pharmacy`, `other`) per tenant. Names are matched ignoring case, Vietnamese accents and spacing, so `BV Chợ Rẫy` and `BV CHO RAY` are one provider.                                                                                  | ✅ B   |
| HW-REC-6 | **Edits and history**: approved observations and findings can be edited or deleted by editors. Every change keeps who, when, and the old value in an audit table.                                                                                                                                         | ✅ B   |

## 5. Import

The goal is to get the bookshelf into the app with as little effort as possible, then keep new results flowing in as they arrive.

| ID       | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Status |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| HW-IMP-1 | **Inbox**: every import lands in the tenant's inbox first, as an inbox item holding one or more files. The engine answers `202` as soon as the files are stored, before any reading. A file whose SHA-256 is already stored in the tenant is reported as a duplicate and not stored again.                                                                                                                                                                                                                                                                                                                                                                                                               | ✅ B   |
| HW-IMP-2 | **Accepted files**: PDF, JPEG, PNG, WebP and HEIC, sniffed from the bytes, not trusted from the name. Limits per file and per batch are settings (`HW_MAX_FILE_MB`, default 50; `HW_MAX_BATCH_MB`, default 200).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | ✅ B   |
| HW-IMP-3 | **Web upload**: drag and drop or pick many files at once, or a whole folder. Each file becomes its own inbox item unless the user ticks _these pages are one document_.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | ✅ B   |
| HW-IMP-4 | **iPhone Shortcut**: a _Send to Health Watcher_ Shortcut in the share sheet posts PDFs and images to `POST /api/inbox` with a personal upload token (HW-AUTH-3) over Tailscale. It works from any app's share sheet: a scan from the Notes or Files document scanner, a PDF from Zalo or Mail, a photo. A setup guide lives in `_setup/iphone-shortcut.md`.                                                                                                                                                                                                                                                                                                                                              | ✅ B   |
| HW-IMP-5 | **Phone camera in the browser**: the web app works in Safari on the phone and can be added to the home screen. An _Add pages_ button opens the camera, takes several pages in a row and sends them as one inbox item.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | ✅ B   |
| HW-IMP-6 | **Backlog mode**: for the first big import, the user picks the person once and scans a stack. The inbox groups items by the date and provider read from them (HW-READ-3) and suggests one visit per group, so the user approves visits, not single pages.                                                                                                                                                                                                                                                                                                                                                                                                                                                | ✅ B   |
| HW-IMP-7 | **Imaging films**: the guide explains how to photograph a film (against a window or a white screen at full brightness, no flash, the whole film in frame). A film photo is stored as `imaging_film` and linked to the visit. The app shows it but never reads it with AI (D5). The written radiology report is the searchable part. Built: an item with too little text, such as a film photo, is skipped without an AI call, and _Don't read with AI_ turns reading off for any item. The photography guide opens from the upload panel and from the filing form of an item that was not read.                                                                                                          | ✅ B   |
| HW-IMP-8 | **Record books** (sổ khám bệnh): each photographed page is a `record_book_page` document. Handwriting is read on a best-effort basis and every reading needs approval like any other. Not yet measured on real handwriting. | 🟡 B~  |

## 6. Reading documents

| ID        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Status |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| HW-READ-1 | **Local text first**: a background worker runs every file through `mac-ocr` (`--lang vi-VT,en-US`, JSON output). PDF text layers are used when present, OCR otherwise. Page text is stored and indexed for search (HW-FIND-2) without any AI call.                                                                                                                                                                                                                                                                                                                                                  | ✅ B   |
| HW-READ-2 | **Page images**: each PDF page is rendered to a JPEG for the viewer and for AI reading (D4).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | ✅ B   |
| HW-READ-3 | **AI reading**: the worker sends the page images and OCR text to the AI provider (HW-AI-1) with a strict JSON schema. The reading proposes: person (from the name on the paper, matched to the tenant's people), date, provider, visit type, document kind, observations (HW-REC-3) and findings (HW-REC-4). Each value carries the page it came from and a confidence from 0 to 100. Images and text go in one request, both masked first (HW-AI-7): the image fixes OCR misreads and the text pins exact digits (D6). Person, birth year and sex come from the local match, never from the model. | ✅ B   |
| HW-READ-4 | **Drafts and approval**: an AI reading becomes drafts, never records. The review page shows the page image beside the drafts, highlights low-confidence values, and lets the user edit, approve or reject. Nothing counts in charts or reviews until approved.                                                                                                                                                                                                                                                                                                                                      | ✅ B   |
| HW-READ-5 | **Units and analyte matching**: on reading, each analyte name is matched to the metric catalog by its known names in Vietnamese and English (`Glucose`, `Đường huyết`, `GLU`). An unmatched analyte stays as written and can be linked to a catalog entry by hand. The link is remembered for that provider.                                                                                                                                                                                                                                                                                        | ✅ B   |
| HW-READ-6 | **Retries**: provider failures retry with backoff (1, 5, 30 minutes, then 6 hours), up to 5 attempts, then the item is marked failed with the error and a _Retry_ button. With AI not configured, items stay at OCR-only and can still be filed by hand.                                                                                                                                                                                                                                                                                                                                            | ✅ B   |
| HW-READ-7 | **Manual entry**: a visit, document metadata, observations and findings can all be entered by hand, without AI.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | ✅ B   |

## 9. AI health review

The review is for reference only. Every screen that shows AI output says so, and says to see a doctor for any decision.

| ID      | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Status |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| HW-AI-1 | **Provider**: any OpenAI-compatible endpoint, ai-gateway by default, through `AI_BASE_URL`, `AI_API_KEY` and `AI_TIMEOUT_SECONDS`. Requests use the Responses API (`POST /v1/responses`) with `store: false`. The model is always `gpt-6-luna` at reasoning effort `low` (D6); it is not a setting. Built for reading; the review comes with phase 5. Leaving `AI_BASE_URL` empty turns AI reading off.                                                                                                                                                                                                                                                                    | 🟡 B~  |
| HW-AI-2 | **Input**: a review reads only approved observations and findings for one person, plus age and sex. It never reads images.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | ⚪ P   |
| HW-AI-3 | **Output** (strict JSON, rendered by the UI): a short summary; per metric, the trend and how the latest value sits against the paper's range; patterns across metrics; questions to ask a doctor; and for each statement its source, either the paper's range or a named guideline with its year (e.g. ADA Standards of Care 2026 for HbA1c, KDIGO for eGFR).                                                                                                                                                                                                                                                                                                              | ⚪ P   |
| HW-AI-4 | **Rules in the prompt and checked in code**: no diagnosis, no drug or dose advice, no statement without a source. A response that breaks the schema or has a statement with no source is rejected and not shown.                                                                                                                                                                                                                                                                                                                                                                                                                                                           | ⚪ P   |
| HW-AI-5 | **Urgent values**: a value the paper marks critical, or one past a threshold in the catalog's curated critical list (each threshold cites its source), shows a banner telling the user to contact a doctor soon. This comes from code, not from the model.                                                                                                                                                                                                                                                                                                                                                                                                                 | ⚪ P   |
| HW-AI-6 | **Stored reviews**: each review is saved with the model id, the date, and a hash of its input. A review whose input has changed since is marked _out of date_.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | ⚪ P   |
| HW-AI-7 | **Personal data stays local**: before any AI call, the engine finds personal lines in the mac-ocr output on the Mac: lines with labels such as `Họ tên`, `Năm sinh`, `Mã BN`, `BHYT`, `CCCD`, `Địa chỉ`, `SĐT`, `BS.`; names of the tenant's people matched without diacritics, so OCR misspellings still match; and runs of 9 or more digits. Those lines are blacked out in the page image and replaced with `[ẩn]` in the text. Barcodes and QR codes are blacked out too. A page with a header the engine can't read with confidence is not sent until the user checks the masked preview. The masked image is stored, so the review page shows exactly what was sent. | ✅ B   |

## 11. Architecture

- **Engine**: Go, Fiber v2, `log/slog`, `modernc.org/sqlite`, `golang.org/x/crypto/argon2`. `internal/app` wires the services for `main.go` and the commands. Routes are plain Fiber routes; an OpenAPI document can follow when an outside client needs one.
- **Layers**: `domain/` (types and rules, no I/O), `port/` (interfaces: repositories, file store, OCR, AI), `service/` (use cases; every method takes a `domain.Scope` holding the user, tenant and role), `adapter/` (sqlite, filestore, macocr, ai/openai, fiber).
- **Tenant scope**: a Fiber middleware resolves the session and the active tenant into a `domain.Scope` and puts it in the request context. Services read the scope, check the role, and pass `scope.TenantID` to repositories. Repositories have no method that reads tenant data without a tenant id.
- **Workers**: one in-process worker pool for OCR, page rendering and AI reading, driven by a `jobs` table (status, attempts, `next_attempt_at`), so work survives restarts.
- **UI**: SvelteKit with runes, Tailwind v4, hand-made components in `ui/src/lib/components`, fetch client with typed `ApiError` (copied from wealth-management, not shared, until a shared lib is worth it). Charts follow the repo's dataviz guidance.

## 12. Test plan

- **Go unit tests** for domain rules (unit conversion, analyte matching, accent folding, range flags) and services against hand-written fakes in `internal/fakes`. BDD names: `TestGiven...When...Then...`.
- **Repository tests** against a temporary SQLite file, including the cross-tenant suite (HW-TEN-6).
- **HTTP tests** through Fiber's `app.Test` for auth, roles, CSRF and upload limits.
- **AI tests** with a fake provider returning recorded JSON. A small set of live tests, gated by `RUN_LIVE_AI_TESTS=true`, runs synthetic documents (made-up names and values, never real records) through the real provider.
- **UI tests**: vitest with jsdom and `@testing-library/svelte`.
- **Fixtures**: synthetic lab reports, prescriptions and radiology reports in Vietnamese and English, generated for tests. Real documents never enter the repo.

| D6  | Page images to the AI provider.            | **Decided 2026-10-21**: send a locally masked page image together with masked OCR text (HW-AI-7); the user wants personal data handled on the Mac and the AI used only for reading. Test on a synthetic Vietnamese lab report (18 rows), gpt-6-luna at low effort: masked image plus masked text read all 90 lab fields correctly on both a 200 dpi scan and a blurred, tilted phone photo, in two runs each, and returned no personal field. Unmasked, image plus text scored 97/97, image only 96/97, OCR text only 88/97 (flags and units on the wrong rows, `5.82` read as `5.2`, diacritics lost, `µmol/L` as `umol/L`), because Vision returns table columns one after another. Masks must follow the rotated line box: a straight box on a tilted photo clipped the hospital name above. Rejected: unmasked images (names and ID numbers reach the provider), text only (too weak on tables). |
